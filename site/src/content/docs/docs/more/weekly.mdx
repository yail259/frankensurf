Every Monday a fresh GitHub machine reads the same 150 sites (held-out set 7, picked blind on 10
October 2026), once with each tool on its own and once with Frankensurf. Every read is judged by the
same content checks as the [launch benchmark](/docs/more/benchmarks/). The sites stay the same so the
trend means something. Sites change, tools change, and this shows whether the result holds.

**[See it charted: every site, every tool, speed and trend →](/benchmarks/)**

It runs from a data-centre address, which sites wall more often than a home connection, so every
rate here is lower than the headline numbers. Compare the tools with each other, week by week.
Paid tools appear when their keys are configured for the run.

## Optional local evidence

For a public-only benchmark, an operator can create a new owner-only directory
outside the repository and set `TOOLBENCH_EVIDENCE_DIR` to its absolute path.
The benchmark saves the acquired content needed to repeat its validity checks,
and includes a filename and SHA-256 digest in each row. Run
`python scripts/verify_benchmark_evidence.py ROWS EVIDENCE_DIR` to replay those
checks offline. Capture currently requires a POSIX filesystem with ownership
and no-follow support; the operator can set `TOOLBENCH_EVIDENCE_MAX_BYTES` to
the maximum size of each artifact. Reuse of a run directory is rejected.

These files contain page content and URLs, can include sensitive or licensed
material from the page, and must not be committed or published. Identity-backed
cases are refused when capture is enabled. Set retention and deletion rules
before collecting content. A matching digest links a row to its artifact; it
is not a signature, an independent judge of content, a complete acquisition
trace or a provider invoice. An oversized or failed write stops capture rather
than silently saving a truncated artifact.
